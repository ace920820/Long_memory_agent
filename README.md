# 智能长期记忆对话系统

一个基于长期记忆的智能对话系统，通过管理和利用历史对话内容，提供个性化且连贯的对话体验。系统能够像人类一样形成并利用长期记忆，实现更自然的人机交互。

## 🌟 主要特点

### 📚 知识库管理（新增）
- **文档管理**
  - 多格式文档支持（TXT、DOCX、PDF、MD）
  - 文档上传、预览、编辑和删除
  - 智能文档分段与索引
  - 基于语义的文档内容检索
- **内容处理**
  - 智能文本分块：基于语义的递归切分
  - 动态块大小调整：保持语义完整性
  - 智能重叠处理：确保上下文连贯
  - 文档内容实时预览

### 🧠 动态记忆管理（新增）
- **动态聚类**：
  - 自动聚类：不依赖手动预设分类，而是基于记忆内容的相似性，动态生成合适的分类；
  - 层级自适应：当新的记忆项加入时，自动调整已有分类层级，可能会创建新的子类别、合并相似类别或调整类别归属；
- **记忆关联管理**：
  - 管理记忆项之间的关联（如某个技术栈在不同项目中的应用）也应随时间演化；
- **可视化支持**：
  - 使用图结构（而不是树结构）来管理和展示这些信息，使其更直观；
- **语义理解**：
  - 利用 NLP 技术（如 BERT、TF-IDF、Word2Vec 等）分析记忆间的语义关系，而不是单纯依赖关键词匹配或依存句法分析。

### 🧠 智能记忆管理
- **记忆管理界面**
  - 批量管理功能
  - 高级检索功能
  - 记忆详细信息显示
  - 优化的删除操作流程
  - 记忆访问统计与分析
  - 记忆簇可视化展示
- **向量模型**
  - BGE (BAAI General Embedding) 中文向量模型
  - bge-small-zh-v1.5 作为默认模型
  - 512维向量表示
  - 优秀的中文语义理解能力
- **记忆操作**
  - 智能记忆拆分
  - 自动记忆清理
  - 记忆重构优化
- **动态记忆聚类（新增）**
  - 自适应聚类：根据语义相似度动态形成记忆簇
  - 实时更新：新记忆自动加入相关簇或形成新簇
  - 簇内优化：
    - 自动合并相似度高的记忆簇
    - 定期优化簇内记忆排序
    - 智能处理簇内冗余信息
  - 簇级摘要：
    - 为每个记忆簇生成动态摘要
    - 基于 TF-IDF 和关键词提取的摘要生成
    - 摘要实时更新机制
  - 访问优化：
    - 簇级别的访问统计
    - 基于访问频率的簇优先级调整
    - 智能缓存热门记忆簇
  - 记忆关联：
    - 跨簇记忆关联分析
    - 建立记忆关系图谱
    - 支持复杂的记忆检索路径

### 💬 对话能力
- **上下文感知**：多层次上下文构建（关键、相关、背景信息）
- **记忆融合**：智能将相关记忆融入对话生成
- **个性化回复**：基于用户历史偏好的回答生成
- **对话连贯性**：维护最近对话历史，确保交互连贯

### 🛠 知识检索增强
- **向量索引**：基于FAISS的高效向量检索
- **三阶段检索策略**
  - 第一阶段：BGE Embedding 向量检索（20%权重）
  - 第二阶段：BGE-Rerank 精确重排序（50%权重）
  - 第三阶段：记忆优先级评分（30%权重）
  - 加权融合策略：综合考虑向量相似度、重排序分数和记忆优先级
- **记忆优先级机制**
  - 时间因子：改进的多阶段时间衰减计算
    - 24小时内：缓慢线性衰减，保持高优先级
    - 1周内：中等速度衰减，保持中等优先级
    - 1周后：对数衰减，长期保持基础优先级
  - 重要性因子：不同类型记忆的权重区分
  - 访问因子：基于访问频率的重要性评估
  - 自动清理：优先级阈值过滤
- **智能匹配**
  - 基于语义的文档匹配
  - 动态相似度阈值
  - 详细的匹配得分日志
- **持久化存储**：文档和索引的本地持久化

### 🛠️ 系统架构
- **模块化设计**：核心功能解耦，便于扩展
- **配置驱动**：通过YAML配置文件管理系统参数
- **完整日志**：详细的运行日志，便于调试和监控

### 环境变量配置
在运行系统前，需要配置以下环境变量：

```bash
# 基础环境变量
PYTHONUNBUFFERED=1

# Deepseek API配置
DASHSCOPE_API_KEY=your_api_key  # 替换为你的API密钥
DASHSCOPE_MODEL=qwen-plus       # 可选模型：qwen-plus, qwen-max, 等
```

你可以通过以下方式设置环境变量：

1. 在系统环境变量中设置
2. 在 `.env` 文件中配置
3. 在启动命令中指定：
```bash
export DASHSCOPE_API_KEY=your_api_key
export DASHSCOPE_MODEL=qwen-plus
python main.py
```

### 安装步骤

1. 克隆项目
```bash
git clone https://github.com/ace920820/long-memory-chat.git
cd long-memory-chat
```

2. 安装依赖
```bash
pip install -r requirements.txt
```

3. 初始化配置和记忆文件
```bash
python scripts/init_memory_file.py
```

4. 启动服务
```bash
python main.py
```

5. 访问系统
浏览器打开 `http://localhost:5000`

## ⚙️ 配置说明

系统配置（config/config.yaml）：
```yaml
server:
  host: "0.0.0.0"
  port: 5000

memory:
  max_memories: 1000
  clean_threshold: 0.85
  similarity_threshold: 0.45
  access_history_limit: 10  # 保存最近访问历史的数量
  priority_weights:
    time: 0.3
    importance: 0.4
    access: 0.3
  intra_cluster_recall:
    enabled: true  # 是否启用簇内召回补偿
    keyword_match_weight: 0.6  # 关键词匹配权重
    tfidf_similarity_weight: 0.4  # TF-IDF相似度权重
    top_k_compensate: 3  # 补偿召回的记忆数量
    min_compensate_score: 0.3  # 最小补偿分数阈值
```

## 🔌 API接口

### 记忆管理接口
- `POST /api/memories/access`: 记录记忆访问
- `POST /api/memories/priority`: 更新记忆优先级
- `POST /api/memories/clean-low-priority`: 清理低优先级记忆

### 知识库接口
- `POST /api/documents`: 添加新文档
- `PUT /api/documents/{id}`: 更新文档
- `DELETE /api/documents/{id}`: 删除文档
- `GET /api/documents/search`: 检索相关文档

### 2025年2月更新
#### 1. 记忆检索机制优化
实现了"综合召回 vs 精准召回"的双路召回机制，包括：

1. **查询分类器 (QueryClassifier)**
   - 基于关键词分析，判断用户查询意图
   - 支持动态添加关键词，实现分类策略的灵活调整
   - 综合召回关键词：概述、总结、整体等
   - 精准召回关键词：具体、详细、精确等

2. **精准召回 (PreciseRetriever)**
   - 针对具体信息查询场景
   - 直接返回最相关的记忆片段
   - 支持自定义召回数量和相似度阈值
   - 对召回结果进行重排序，确保返回最相关内容

3. **综合召回 (ComprehensiveRetriever)**
   - 针对主题概览查询场景
   - 基于动态记忆聚类，返回相关记忆簇的摘要
   - 提供主题的整体概览和关键信息
   - 支持自定义相似度阈值

4. **记忆召回管理器 (RetrievalManager)**
   - 作为记忆召回的统一入口
   - 根据查询意图自动选择召回策略
   - 协调精准召回和综合召回
   - 支持上下文信息处理
   - 提供灵活的配置参数调整

5. **🚀记忆召回机制增强**
   - 引入"综合召回 vs 精准召回"策略，提升记忆检索的灵活性
   - 新增簇内召回补偿机制，解决低相似度但高关联度记忆的召回问题
   
6. **🔍簇内召回补偿（Intra-Cluster Recall Compensation）**
   - 基于 TF-IDF 和共现词分析，计算记忆关键词权重
   - 提高查询与记忆簇关键词匹配度低但仍相关的记忆的召回概率
   - 动态调整记忆召回策略，增强系统的语义理解能力
   - 新增配置开关，支持灵活控制补偿机制

## 角色系统

### 角色配置
角色配置位于 `prompts/roles` 目录下，通过 YAML 文件进行管理。系统会自动从配置文件中读取可用的角色列表和描述信息。

配置示例：
```yaml
available_roles:
  - assistant
  - santa
  - frank
  - reindeer

role_descriptions:
  assistant: 个人助理
  santa: 圣诞老人
  frank: 弗兰克
  reindeer: 驯鹿
```

### 角色切换
- 系统会根据配置文件自动生成角色选择按钮
- 可以通过点击按钮切换不同的角色
- 每次切换角色时会显示相应的提示信息
- 默认角色可在配置文件中设置

### API 接口
- `/get_available_roles`: 获取所有可用的角色列表和描述
- `/get_default_role`: 获取默认角色设置
- `/set_role`: 切换当前对话角色

### 扩展新角色
要添加新的对话角色，只需要：
1. 在 `roles.json` 中添加角色配置
2. 确保在 `available_roles` 列表中包含新角色
3. 在 `role_descriptions` 中添加角色的显示名称

前端会自动识别新增的角色并生成对应的选择按钮，无需修改前端代码。
