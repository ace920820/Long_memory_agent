# 智能长期记忆对话系统

一个基于长期记忆的智能对话系统，通过管理和利用历史对话内容，提供个性化且连贯的对话体验。系统能够像人类一样形成并利用长期记忆，实现更自然的人机交互。

## 🌟 主要特点

### 📚 知识库管理
- **文档处理**
  - 支持多种格式：PDF、Word、Markdown等
  - 智能分段：基于语义的文档分割
  - 向量化存储：高效的文档检索
- **RAPTOR树形结构**
  - 递归式文本处理：
    - 自底向上的文本块嵌入
    - 多层次语义聚类
    - 层级化信息总结
  - 树形组织优化：
    - 动态节点分裂与合并
    - 自适应层级调整
    - 智能平衡维护
  - 高效检索机制：
    - 折叠树检索策略
    - 多粒度匹配优化
    - k近邻快速检索
- **文档管理**
  - 智能重叠处理：确保上下文连贯
  - 文档内容实时预览

### 🧠 智能记忆管理
- **记忆管理界面**
  - 批量管理功能
  - 高级检索功能
  - 记忆详细信息显示
  - 优化的删除操作流程
  - 记忆访问统计与分析
  - 树形结构可视化
- **向量模型**
  - BGE (BAAI General Embedding) 中文向量模型
  - bge-small-zh-v1.5 作为默认模型
  - 512维向量表示
  - 优秀的中文语义理解能力
- **记忆操作**
  - 自动记忆清理
  - 记忆重构优化
- **增量更新与局部重构**
  - 增量式节点插入：每轮对话只插入新节点，不重构整个树
  - 定期重构机制：根据配置的对话轮数触发树重构
  - 性能优化：
    - 避免频繁重构带来的性能开销
    - 保持树结构的稳定性
    - 优化内存使用效率
  - 配置灵活：
    - 可配置重构间隔轮数
    - 可开关重构功能

    - 自适应层级深度调整

  - 语义相关性管理：
    - 基于向量相似度的节点关联
    - 跨层级语义链接
    - 动态更新关联强度
  - 检索增强生成：
    - 多层级并行检索
    - 上下文感知的结果合并
    - 动态权重调整
  - 记忆优化机制：
    - 热点记忆缓存
    - 冷数据自动归档
    - 重复信息智能合并
  - 树形结构维护：
    - 定期结构优化
    - 自动平衡调整

  - 高效检索策略：
    - 折叠树检索

  - 记忆访问优化：

- **记忆融合**：智能将相关记忆融入对话生成
- **个性化回复**：基于用户历史偏好的回答生成
- **对话连贯性**：维护最近对话历史，确保交互连贯

### 🛠 知识检索增强
- **向量索引**：基于FAISS的高效向量检索
- **三阶段检索策略**
  - 第一阶段：BGE Embedding 向量检索（20%权重）
  - 第二阶段：BGE-Rerank 精确重排序（50%权重）
  - 第三阶段：记忆优先级评分（30%权重）
  - 加权融合策略：综合考虑向量相似度、重排序分数和记忆优先级
- **记忆优先级机制**
  - 时间因子：改进的多阶段时间衰减计算
    - 24小时内：缓慢线性衰减，保持高优先级
    - 1周内：中等速度衰减，保持中等优先级
    - 1周后：对数衰减，长期保持基础优先级
  - 重要性因子：不同类型记忆的权重区分
  - 访问因子：基于访问频率的重要性评估
  - 自动清理：优先级阈值过滤
- **智能匹配**
  - 基于语义的文档匹配
  - 动态相似度阈值
  - 详细的匹配得分日志
- **持久化存储**：文档和索引的本地持久化

- **高效检索机制**

  - 上下文感知：保持检索结果的语义连贯性
- **API接口**
  - 文档管理：支持文档的添加、查询和更新

### 环境变量配置
在运行系统前，需要配置以下环境变量：

```bash
# 基础环境变量
PYTHONUNBUFFERED=1

# Deepseek API配置
DASHSCOPE_API_KEY=your_api_key  # 替换为你的API密钥
DASHSCOPE_MODEL=qwen-plus       # 可选模型：qwen-plus, qwen-max, 等
```

你可以通过以下方式设置环境变量：

1. 在系统环境变量中设置
2. 在 `.env` 文件中配置
3. 在启动命令中指定：
```bash
export DASHSCOPE_API_KEY=your_api_key
export DASHSCOPE_MODEL=qwen-plus
python main.py
```

### 安装步骤

1. 克隆项目
```bash
git clone https://github.com/ace920820/long-memory-chat.git
cd long-memory-chat
```

2. 安装依赖
```bash
pip install -r requirements.txt
```

3. 初始化配置和记忆文件
```bash
python scripts/init_memory_file.py
```

4. 启动服务
```bash
python main.py
```

5. 访问系统
浏览器打开 `http://localhost:5000`

## ⚙️ 配置说明

系统配置（config/config.yaml）：
```yaml
server:
  host: "0.0.0.0"
  port: 5000

memory:
  max_memories: 1000
  clean_threshold: 0.85
  similarity_threshold: 0.45
  access_history_limit: 10  # 保存最近访问历史的数量
  priority_weights:
    time: 0.3
    importance: 0.4
    access: 0.3
  intra_cluster_recall:
    enabled: true  # 是否启用簇内召回补偿
    keyword_match_weight: 0.6  # 关键词匹配权重
    tfidf_similarity_weight: 0.4  # TF-IDF相似度权重
    top_k_compensate: 3  # 补偿召回的记忆数量
    min_compensate_score: 0.3  # 最小补偿分数阈值
```

## 角色系统

### 角色配置
角色配置位于 `prompts/roles` 目录下，通过 YAML 文件进行管理。系统会自动从配置文件中读取可用的角色列表和描述信息。

配置示例：
```yaml
available_roles:
  - assistant
  - santa
  - frank
  - reindeer

role_descriptions:
  assistant: 个人助理
  santa: 圣诞老人
  frank: 弗兰克
  reindeer: 驯鹿
```

### 角色切换
- 系统会根据配置文件自动生成角色选择按钮
- 可以通过点击按钮切换不同的角色
- 每次切换角色时会显示相应的提示信息
- 默认角色可在配置文件中设置

### API 接口
- `/get_available_roles`: 获取所有可用的角色列表和描述
- `/get_default_role`: 获取默认角色设置
- `/set_role`: 切换当前对话角色

### 扩展新角色
要添加新的对话角色，只需要：
1. 在 `roles.json` 中添加角色配置
2. 确保在 `available_roles` 列表中包含新角色
3. 在 `role_descriptions` 中添加角色的显示名称

前端会自动识别新增的角色并生成对应的选择按钮，无需修改前端代码。
